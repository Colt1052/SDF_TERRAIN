● Here's what I built:

  InventoryDebugView.cs — a new MonoBehaviour in Runtime/Resources/ that renders
  an inventory overlay in-game.

  How it works

  1. Auto-discovers the TerrainExcavationSystem by looking for a PlanetDemo on
     the same GameObject (or uses the serialized excavationSystem field).
  2. Reads all non-empty slots from the Inventory each frame via OnGUI.
  3. Renders a dark semi-transparent panel (top-left) with:
     - "Inventory" header
     - Per-resource rows: color swatch (from MaterialDatabase, or a
       deterministic hash fallback), formatted name ("iron_ore" → "Iron Ore"),
       and quantity (right-aligned)
     - Shows "(empty)" if there are no resources
  4. Toggle visibility with Tab (configurable in Inspector).

  How to use

  1. Add the InventoryDebugView component to the same GameObject as your
     PlanetDemo (the one that creates the TerrainExcavationSystem in Start()).
  2. Play the scene — the panel appears in the top-left corner immediately.
  3. Mine some terrain (left-click) to collect resources — the inventory updates
     live.
  4. Press Tab to hide/show the menu.

  No .guiskin asset needed — all styles are built at runtime. The component
  follows the project's existing debug-view pattern (SDFDebugView,
  MaterialDebugView, etc.).

  The issue is in TerrainEdit.SampleContribution() — the clamping logic is 
  inverted for placement edits. Here's the chain:

  1. Excavate() creates isAdditive: true, clamped: false — correct, unbounded
     digging
  2. Place() creates isAdditive: false, clamped: true — intended to limit
     placement to the brush area
  3. But the clamp check contribution > 0f is wrong for non-additive edits:
     - For non-additive, contribution = -(radius - distance)
     - Inside the brush: contribution is positive → clamped to MaxValue → Min
       skips it → nothing is placed
     - Outside the brush: contribution is negative → NOT clamped → Min applies
       it → entire world becomes solid

  This means after any placement, everything outside the brush becomes solid.
  Mining air elsewhere samples as solid because the SDF is globally negative,
  yielding resources from geological-layer material.

  Even without placement, the isAdditive flag semantics are backwards relative
  to the naming — "additive" removes terrain (raises SDF toward air),
  "non-additive" adds terrain. This makes the excavation system fragile.
