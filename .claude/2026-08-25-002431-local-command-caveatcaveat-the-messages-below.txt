  it should be transitions / solidBefore. This causes under-yield when the
  brush only partially overlaps solid terrain (the "crescent moon" case).

  Here's why: when you mine a crescent, the volumes sampled come only from solid
  cells. But then you scale those volumes by transitions/totalSamples, diluting
  the yield with all the air samples that contributed nothing. Placing
  correctly charges transitions × areaPerSample × yieldRate. The two only match
  when every sample is solid.

● The root cause is CSG interference between overlapping brushes. When you drag,
  each placement brush's cone modifies the SDF values at nearby cells. This
  shifts which sample cells cross the zero threshold for subsequent brushes,
  making transitions differ between mine and place even at the same position.

  Example: Place B raises SDF values at cells near its edge from -1.5 to -0.2
  (still solid). When place A follows, those cells are now "closer to air" — a
  fewer-cone from A can't push them as far. Conversely, mining sees more cells
  flip because the SDF wasn't pre-shifted by previous mines.

  Fix: Charge based on the pre-edit count only (solid cells for mining, air
  cells for placing). This is symmetric because:
  1. Overlapping mines: second mine at same spot sees 0 solid → yields 0
     (air-center check prevents edge grind)
  2. Overlapping places: second place at same spot sees 0 air → charges 0
  3. Both use count × areaPerSample × yieldRate — identical formula, identical
     result per brush position

● I see the issue. When you drag, a sequence of overlapping mine brushes
  produces more total transitions than the corresponding place brushes. This is
  because of CSG interference: after mine A raises the SDF, mine B's cone starts
  from a higher SDF and gets fewer transitions. But when placing, place A's
  cone starts from the already-mined SDF and gets more transitions, leaving
  place B with fewer. The mine-side "overcounts" because each mine claims cells
  that an earlier mine already partially raised.

  The fix: track the mine brushes during a drag, then replay them in reverse 
  order when placing. This guarantees the same per-brush CSG state and thus the
  same transitions.
