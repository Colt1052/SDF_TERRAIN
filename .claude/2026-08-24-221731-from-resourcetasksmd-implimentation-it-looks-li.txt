● I've traced through both bugs. Here's what I found:

  ---

  Bug 1: Material Loss (Root Cause)

  TerrainExcavationSystem.Place() line 207 creates a TerrainEdit with
  isAdditive: false (non-additive). The SampleContribution returns -(radius - 
  distance) which becomes increasingly positive far from the brush center.
  Combined via Mathf.Min, this corrupts the SDF globally.

  For example, placing at (0, 52) on a planet centered at origin (radius 50):
  - At center (0,0): contribution = 48, Min(-50, 48) = -50 — still solid ✓
  - At point (0, 51): base SDF = 1 (air), contribution = -1, Min(1, -1) = -1 —
    now solid ✗

  This creates a "bridge" of solid material from the planet surface to the
  placed brush, and corrupts depth readings everywhere.

  This also explains "no stone": the corrupted SDF gives wrong depth values to
  GeologicalLayerGenerator.Sample. At a point that should be depth 5 (stone),
  the SDF might read -48, returning mantle instead.

  Bug 2: Material Loss on Pickup/Place

  This is a consequence of the SDF corruption — when you re-mine placed terrain,
  the depth readings are wrong, sampling garbage materials or air instead of
  the placed material.

  ---

  Fix

  Add a Clamped flag to TerrainEdit. When true, non-additive (place) edits
  return 0 outside the brush so Min naturally ignores them. Removal edits stay
  unbounded (needed for smooth meshing per the existing design).

  Summary of Changes

  Root Cause

  Both bugs stemmed from a single SDF corruption in
  TerrainExcavationSystem.Place():

  TerrainEdit.SampleContribution for non-additive edits returns -(radius - 
  distance). Far from the brush, this becomes increasingly positive. The CSG
  combine uses Mathf.Min, so:
  - Point in air far from brush: Min(5.0, 48.0) = 5.0 ... looks fine, but
  - Point in air between the planet surface and brush: Min(1.0, -1.0) = -1.0 ...
    now solid

  This creates a "bridge" of solid terrain from the brush back toward the
  planet. The SDF depth is corrupted everywhere within the bridge region. When
  GeologicalLayerGenerator.Sample reads this corrupted depth, it returns the
  wrong layer — e.g., reading depth 48 instead of depth 5, so "mantle" appears
  where "stone" should be. This explains both "only seeing dirt and mantle" and
  "losing material on pickup/place".

  Fix: TerrainEdit.Clamped

  Files changed:

  1. TerrainEdit.cs — Added bool Clamped field. When true and outside the brush,
     SampleContribution returns float.MaxValue so Mathf.Min(base, MaxValue) =
     base, naturally skipping the combine without modifying the SDF.
  2. TerrainExcavationSystem.cs — Place() now creates the terrain edit with
     clamped: true.
  3. WorldSaveData.cs — SerializableTerrainEdit persists the Clamped flag for
     save/load round-trips.

  Existing callers (brushes, tests, strikers) default clamped to false and are
  unaffected.
