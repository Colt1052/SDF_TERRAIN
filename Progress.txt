     Plan: Dynamic Chunk Expansion for Off-Grid Edits

     Context

     Currently, ChunkGrid creates a fixed grid of chunks covering the planet's
     bounding box (±radius). When a brush edit occurs outside this grid,
     ChunksInRect() clamps to the grid edge and silently dirties an edge chunk
     instead — the edit is visually lost in empty space. Players cannot build
     terrain or structures in empty space outside the planet.

     The TerrainField SDF itself has no bounds — it can be sampled at any
     position. The limitation is purely in the chunk grid and renderer, which
     assume a fixed set of chunks created at initialization.

     This change makes the chunk grid dynamically expandable: when an edit
     targets a region with no chunk, new chunks are created on-demand, rendered,
     and participate in the normal dirty/rebuild pipeline.

     Design Decision: Sparse Chunk Grid

     The current ChunkGrid uses a dense TerrainChunk[] array indexed as row * 
     cols + col. This is efficient for a fixed grid but incompatible with
     dynamic expansion (inserting chunks into the middle of an array is
     expensive, and resizing breaks all existing indices).

     Approach: Convert ChunkGrid to use a Dictionary<long, TerrainChunk> keyed
     by packed (col, row) coordinates. Chunks are assigned sequential indices
     via an auto-incrementing counter. The grid still has a "fixed" region (the
     original planet-covering grid), but can seamlessly extend beyond it.

     This is a clean architectural shift — the grid is no longer "fixed at
     construction" (as stated in the current docstring) but becomes a living,
     expandable data structure. All existing behavior within the original grid
     is preserved.

     Changes by File

     1. TerrainChunk.cs (minor)

     - Add a Key property: packed (col, row) as long (col in high 32 bits, row
       in low 32 bits). This is the dictionary key used by ChunkGrid.
     - No other changes — Index, Col, Row, bounding box properties, and dirty
       state remain unchanged.

     2. ChunkGrid.cs (major refactor)

     - Replace _chunks[] array with Dictionary<long, TerrainChunk> _chunks.
     - Keep _gridMinX, _gridMinY, _cols, _rows for the initial fixed region.
     - Add _nextIndex (auto-incrementing counter for sequential chunk indices).
     - GetChunkAt(Vector2): Compute (col, row). If chunk exists in dictionary,
       return it. If position is within original grid bounds, return existing
       edge chunk (current clamping behavior). If outside original grid, create 
       and return the new chunk.
     - GetChunkAtGrid(col, row): Look up in dictionary. Throw if not found
       (preserves current behavior for existing grid; callers outside the grid
       should use GetChunkAt).
     - ChunksInRect: Compute (col, row) range. For each coordinate pair, get or
       create the chunk. Add all indices to result. No clamping — new chunks are
       created as needed.
     - GetNeighbor: Look up neighbor coordinates in dictionary. Return null if
       neighbor doesn't exist (preserves current behavior at grid edge; new
       chunks simply have no neighbors until those positions are also created).
     - DirtyChunks(): Iterate _chunks.Values instead of array.
     - ClearAllDirty(): Iterate _chunks.Values.
     - ChunkCount: Return _chunks.Count.
     - AllChunks: New IEnumerable<TerrainChunk> property returning
       _chunks.Values (for callers that need to iterate all chunks without
       assuming contiguous indices).
     - Add helper GetOrCreateChunkAtGrid(col, row) that returns existing chunk
       or creates a new one.

     3. TerrainField.cs (indexing change)

     - Replace _editsByChunk from List<int>[] (array indexed by chunk index) to
       Dictionary<int, List<int>> (dictionary keyed by chunk index).
     - EnableChunkIndexing(ChunkGrid): Iterate all existing chunks and
       initialize empty List<int> entries in the dictionary.
     - IndexEdit: When ChunksInRect returns chunk indices, ensure each has a
       List<int> entry in the dictionary (Handle newly created chunks that
       didn't exist when EnableChunkIndexing was called). Use
       _editsByChunk.GetOrCreate(chunkIndex) pattern.
     - Sample(Vector2, int): Look up edit indices via _editsByChunk[chunkIndex].
     - PruneDeadEdits(): Iterate dictionary entries instead of array.
     - ClearEdits(): Clear all dictionary values.
     - LoadEdits(): Clear and rebuild dictionary entries.

     4. ChunkTerrainRenderer.cs (view management)

     - Replace _chunkViews[] (array indexed by chunk index) with Dictionary<int,
       ChunkView> _chunkViews.
     - Initialize(): After creating initial chunk views, populate the
       dictionary.
     - RebuildChunk(TerrainChunk): Look up view via _chunkViews[chunk.Index]. If
       not found (newly created chunk), create the view first via
       CreateChunkView(chunk).
     - ApplyBrush(): Call ChunksInRect which now creates chunks as needed. After
       marking dirty, ensure chunk views exist for any new chunks before
       calling RebuildDirtyChunks.
     - CreateChunkView(): Accept a TerrainChunk parameter instead of an index;
       use chunk.Index for the GameObject name.

     5. CartesianChunkFieldSampler.cs (no changes)

     - Uses chunk.MinX, chunk.MaxX, chunk.MinY, chunk.MaxY, and chunk.Index —
       all still present on TerrainChunk. No modification needed.

     - Add IEnumerable<TerrainChunk> AllChunks property to ChunkGrid (returns
       _chunks.Values).
     - Change Refresh() to iterate foreach (TerrainChunk chunk in 
       _chunkGrid.AllChunks) instead of by index.

     - TerrainBrush.cs, TerrainEdit.cs, BrushMode.cs: Unaffected.
